# Technical Support Priority Levels

## Page Title
Technical Support Priority Levels

## Summary
Defines four priority levels (P1–P4) for classifying issues when submitting Twingate technical support requests. Proper priority alignment helps route and resolve tickets efficiently.

## Priority Level Reference

| Level | Name | Description | Example |
|-------|------|-------------|---------|
| **P1** | Urgent | Core/mission-critical services critically affected; no workaround | Most users cannot authenticate or access resources |
| **P2** | High | Services functional but degraded; potentially severe impact for multiple users | Connector or Remote Network issue blocking multiple users |
| **P3** | Normal | Non-critical; minor impact on specific users | Individual users having Client or Resource access issues |
| **P4** | Low | Non-impacting; informational | General questions, FYI submissions |

## Key Information
- Priority level should be selected by the reporter when engaging support
- **P1**: Large number of users affected, no workaround available
- **P2**: Multiple users affected, service still responding but degraded
- **P3**: Isolated to specific users, no significant performance impact
- **P4**: No operational impact

## Gotchas
- Accurate priority selection is explicitly requested — avoid inflating priority (e.g., marking informational questions as P1)
- P1 requires both wide user impact **and** no available workaround; partial outages with workarounds may qualify as P2
