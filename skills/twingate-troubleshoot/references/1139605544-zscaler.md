# Using Zscaler Alongside Twingate

## Summary
Zscaler Client Connector intercepts Twingate's TLS sessions on Windows, causing SSL certificate validation failures. The conflict occurs because Zscaler runs as a background service even when the UI is closed. Resolution requires either disabling Zscaler or configuring SSL inspection bypass rules.

## Key Information
- **Affected component**: Twingate Client on Windows
- **Root cause**: Zscaler intercepts Twingate TLS sessions and returns an invalid certificate
- **Scope**: Windows confirmed; macOS/Linux untested but same resolution expected

## Symptoms
Log entries in `Twingate.log` (Windows):
```
[WARN] SSL check error from host: <twingate_network>.twingate.com. SSL Certificate is not pinned!
[ERROR] Failed to validate controller url — The remote certificate is invalid according to the validation procedure.
```

## Resolution Options

### Option 1: Disable Zscaler Service (Full Fix)
- Uninstall Zscaler, OR
- Stop and **disable** the Zscaler Windows service
- ⚠️ Simply exiting the Zscaler UI is **not sufficient** — the service continues running in the background

### Option 2: Configure Zscaler Bypass (Coexistence)

**Step 1 — SSL Inspection Bypass**
1. In Zscaler admin console: `Administration → IP & FQDN Groups → Destination IPv4 Groups`
2. Create a new group for SSL inspection bypass
3. Add `.twingate.com` to the group

**Step 2 — VPN Gateway Hostname Bypass**
1. In Zscaler admin console: `Policy → Zscaler Client Connector Portal → Windows`
2. Edit the applicable policy under `HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY`
3. Add exception: `<tenant>.twingate.com` (replace `<tenant>` with your Twingate tenant name)

**Step 3**
- Push/update the policy on the Zscaler local agent

## Configuration Values
| Field | Value |
|---|---|
| SSL bypass FQDN | `.twingate.com` |
| VPN gateway bypass | `<tenant>.twingate.com` |

## Gotchas
- Exiting Zscaler UI does **not** stop the Windows service — service must be explicitly stopped/disabled
- macOS and Linux compatibility is **unconfirmed and untested**; same bypass approach would apply if issues arise
- Both bypass rules (SSL inspection AND VPN gateway) are required for coexistence — configuring only one is insufficient

## Prerequisites
- Zscaler admin console access with permission to edit IP/FQDN groups and Client Connector policies
- Your Twingate tenant name
