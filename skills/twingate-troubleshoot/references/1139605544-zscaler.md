# ZScaler + Twingate Compatibility

## Page Title
ZScaler Integration / Conflict Resolution

## Summary
ZScaler intercepts Twingate's TLS sessions, returning invalid certificates that prevent the Twingate Client from establishing secure channels. Resolution requires either disabling ZScaler or configuring SSL inspection bypass rules in the ZScaler admin console.

## Key Information
- **Affected component:** Twingate Client (Windows confirmed; macOS/Linux untested)
- **Root cause:** ZScaler performs TLS/SSL inspection, breaking Twingate's certificate pinning
- **ZScaler behavior:** Runs as a Windows service even when the UI is closed — must be fully stopped/disabled, not just exited

## Symptoms
Log entries in `twingate.log` (Windows):
```
[WARN] SSL check error from host: .twingate.com. SSL Certificate is not pinned!
[ERROR] Failed to validate controller url ... The remote certificate is invalid according to the validation procedure.
```

## Resolution Options

### Option A: Disable ZScaler Service (Windows)
Stop and disable the ZScaler Windows service entirely (not just exit the application). Uninstalling is also valid.

### Option B: Configure ZScaler Bypass (Preferred)

**Step 1 — Create SSL Inspection Bypass Group**
- Navigate to: `Administration → IP & FQDN Groups → Destination IPv4 Groups`
- Create a new group for SSL inspection bypass
- Add: `.twingate.com`

**Step 2 — Add VPN Gateway Hostname Bypass**
- Navigate to: `Policy → Zscaler Client Connector Portal → Windows`
- Edit the applicable policy under **HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY**
- Add exception: `.twingate.com` (replace with your tenant subdomain as needed)

**Step 3 — Push Policy Update**
- Apply/update policy on the ZScaler local agent

## Configuration Values
| Field | Value |
|-------|-------|
| Bypass target | `.twingate.com` |
| Bypass type | SSL inspection + VPN gateway hostname |

## Gotchas
- ZScaler service persists after UI exit on Windows — must disable the service, not just quit the app
- macOS and Linux compatibility not confirmed; if issues arise, same resolution approach applies
- Both bypass steps (SSL inspection group **and** hostname bypass policy) are required together

## Prerequisites
- ZScaler admin console access
- Ability to manage Windows services (for Option A)
