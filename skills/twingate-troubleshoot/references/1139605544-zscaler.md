# Using Zscaler alongside Twingate

## Summary
Zscaler Client Connector on Windows can intercept the Twingate TLS session, so the Twingate Client sees an invalid certificate and cannot open secure channels. The fix is to remove or disable Zscaler, or to configure SSL inspection and hostname bypasses for Twingate domains.

## Key Information
- Applies to: Twingate Client on Windows with Zscaler Client Connector. Other platforms are untested, but the same resolution is expected to apply on macOS and Linux.
- The Zscaler service runs even when the app is not connected.
- Exiting the Zscaler program is not enough to stop the interference.

## Prerequisites
- Admin access to the Zscaler admin console.
- Admin rights on the Windows device (to stop or disable services, or to uninstall).
- Your Twingate tenant name.

## Symptoms (Twingate.log on Windows)
- `[WARN] [client] SSL check error from host: <twingate_network>.twingate.com. SSL Certificate is not pinned! [ApiCertificateValidationService.Callback]`
- `[ERROR] [client] Failed to validate controller url [ControllerServerValidator.ValidateAsync]`, with `HttpRequestException` / `WebException` "Could not establish trust relationship for the SSL/TLS secure channel" / `AuthenticationException` "The remote certificate is invalid"

## Step-by-Step

**Option A: Remove Zscaler's interference**
1. Uninstall Zscaler, or stop the Zscaler service and set it to disabled.

**Option B: Run both with bypass config (works in some cases)**
1. In the Zscaler admin console, go to Administration → IP & FQDN Groups → Destination IPv4 Groups.
2. Create a group for SSL inspection bypass and add `.twingate.com`.
3. Go to Policy → Zscaler Client Connector Portal → Windows.
4. Edit the applicable policy. Under HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY, add `<tenant>.twingate.com` as an exception, replacing `<tenant>` with your tenant name.
5. Update the policy on the Zscaler local agent.

## Configuration Values
- SSL inspection bypass group entry: `.twingate.com`
- VPN gateway bypass entry: `<tenant>.twingate.com`
- Zscaler locations: Administration → IP & FQDN Groups → Destination IPv4 Groups; Policy → Zscaler Client Connector Portal → Windows

## Gotchas
- Quitting the Zscaler app does not stop its service. The service must be stopped and disabled, or Zscaler uninstalled.
- The bypass configuration is not guaranteed to work ("in some cases").
- The new policy must be pushed or updated on the local Zscaler agent, or the change will not take effect.
- Only Windows is confirmed. Other platforms are untested.
