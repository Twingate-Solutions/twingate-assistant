# Using Zscaler Alongside Twingate

## Page Title
Using Zscaler alongside Twingate

## Summary
Zscaler Client Connector intercepts Twingate's TLS sessions on Windows, causing SSL certificate validation failures that prevent the Twingate Client from establishing secure channels. Resolution requires either disabling the Zscaler service entirely or configuring SSL inspection bypass rules in Zscaler's admin console.

## Key Information
- **Affected component:** Twingate Client on Windows
- **Root cause:** Zscaler intercepts Twingate TLS sessions and returns an invalid certificate
- **Scope:** Windows confirmed; macOS/Linux untested but likely same behavior/fix
- **Exiting Zscaler app is insufficient** — the Zscaler service runs independently and must be stopped/disabled at the service level

## Prerequisites
- Access to Zscaler admin console (for bypass configuration approach)
- Twingate tenant name available

## Symptoms (Log Indicators)
In `Twingate.log` on Windows:
```
[WARN] SSL check error from host: <twingate_network>.twingate.com. SSL Certificate is not pinned!
[ERROR] Failed to validate controller url ... The remote certificate is invalid according to the validation procedure.
```

## Resolution Options

### Option 1: Remove or Disable Zscaler Service
- Uninstall Zscaler Client Connector, **or**
- Stop and disable the Zscaler Windows service (exiting the Zscaler UI is **not** sufficient)

### Option 2: Configure Zscaler Bypass (Coexistence)

**Step 1 — SSL Inspection Bypass**
1. Zscaler Admin Console → **Administration → IP & FQDN Groups → Destination IPv4 Groups**
2. Create a new group for SSL inspection bypass
3. Add `.twingate.com` to the group

**Step 2 — VPN Gateway Hostname Bypass**
1. Zscaler Admin Console → **Policy → Zscaler Client Connector Portal → Windows**
2. Edit the applicable policy under **HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY**
3. Add exception: `<tenant>.twingate.com` (replace `<tenant>` with your Twingate tenant name)

**Step 3**
- Push/update the policy on the Zscaler local agent

## Configuration Values
| Field | Value |
|-------|-------|
| SSL Inspection Bypass entry | `.twingate.com` |
| VPN Gateway Bypass entry | `<tenant>.twingate.com` |

## Gotchas
- Zscaler service persists after closing the UI — must be disabled at OS service level for full removal approach
- macOS and Linux compatibility is **unconfirmed and untested**; apply same resolution if issues occur
- Both bypass configurations (SSL inspection + VPN gateway) are required for coexistence — partial config may not resolve the issue
