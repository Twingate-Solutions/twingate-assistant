# Using Zscaler alongside Twingate

## Summary
Zscaler Client Connector on Windows can intercept the Twingate TLS session and return an invalid certificate. The Twingate Client then cannot open secure channels. The fix is to remove or disable Zscaler, or to configure SSL inspection and VPN gateway bypasses for Twingate domains.

## Key Information
- Applies to the Twingate Client on Windows with Zscaler Client Connector. Other platforms are untested, but the page says the resolution would be the same for macOS or Linux.
- The Zscaler service on Windows keeps running even when not connected.
- Exiting the Zscaler program is not sufficient to stop the interception.
- Symptoms appear in `Twingate.log`:
  - `[WARN] [client] SSL check error from host: <twingate_network>.twingate.com. SSL Certificate is not pinned!`
  - `[ERROR] [client] Failed to validate controller url`, with `AuthenticationException: The remote certificate is invalid according to the validation procedure.`

## Prerequisites
- Admin access to the Zscaler admin console.
- Your Twingate tenant name.
- Ability to update the policy on the local Zscaler agent.

## Step-by-Step

**Option A: Remove Zscaler**
1. Uninstall Zscaler, or stop the Zscaler service and disable it from running.

**Option B: Run both with bypasses (works in some cases)**
1. In the Zscaler admin console, go to Administration → IP & FQDN Groups → Destination IPv4 Groups.
2. Create a group for SSL inspection bypass and add `.twingate.com`.
3. Go to Policy → Zscaler Client Connector Portal → Windows.
4. Edit the applicable policy. Under HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY, add `<tenant>.twingate.com` as an exception, replacing `<tenant>` with your tenant name.
5. Update the policy on the Zscaler local agent.

## Configuration Values
- SSL inspection bypass group entry: `.twingate.com`
- VPN gateway bypass entry: `<tenant>.twingate.com`
- Log file for diagnosis: `Twingate.log`

## Gotchas
- Quitting the Zscaler app does not stop its service, so interception continues.
- Coexistence is not guaranteed. The page says it is possible only "in some cases".
- The bypass must be applied to the local agent by updating its policy, not just saved in the console.
- Behavior on macOS and Linux is unconfirmed.
