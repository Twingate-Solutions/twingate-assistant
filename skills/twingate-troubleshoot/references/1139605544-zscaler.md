# Using Zscaler Alongside Twingate

## Summary
Zscaler Client Connector intercepts Twingate's TLS sessions on Windows, causing certificate validation failures. Resolution requires either disabling the Zscaler service entirely or configuring SSL inspection bypass rules in Zscaler admin console.

## Key Information
- **Affected component:** Twingate Client on Windows
- **Root cause:** Zscaler intercepts TLS sessions and returns an invalid certificate, breaking Twingate's certificate pinning
- **macOS/Linux:** Not confirmed or tested; same resolution approach expected if issues arise

## Symptoms
Check `Twingate.log` on Windows for:
- `SSL Certificate is not pinned!` warnings from `ApiCertificateValidationService`
- `HttpRequestException` / `AuthenticationException` errors from `ControllerServerValidator`
- Trust relationship failure on SSL/TLS channel establishment

## Prerequisites
- Access to Zscaler admin console (for bypass configuration)
- Or local admin rights to stop/disable Zscaler service on Windows

## Resolution Options

### Option 1: Disable Zscaler Service (Guaranteed Fix)
Uninstall Zscaler **or** stop and disable the Zscaler Windows service.
> **Note:** Exiting the Zscaler app/tray icon is **not sufficient** — the service continues running in the background.

### Option 2: Configure Zscaler Bypass (Coexistence)

**Step 1 — SSL Inspection Bypass**
1. In Zscaler admin console → **Administration → IP & FQDN Groups → Destination IPv4 Groups**
2. Create a new group for SSL inspection bypass
3. Add `.twingate.com` to the group

**Step 2 — VPN Gateway Hostname Bypass**
1. Navigate to **Policy → Zscaler Client Connector Portal → Windows**
2. Edit the applicable policy under **HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY**
3. Add `<tenant>.twingate.com` (replace `<tenant>` with your Twingate tenant name)

**Step 3 — Apply Policy**
- Push/update the policy on the Zscaler local agent

## Configuration Values

| Setting | Value |
|---|---|
| SSL Inspection Bypass FQDN | `.twingate.com` |
| VPN Gateway Bypass Hostname | `<tenant>.twingate.com` |

## Gotchas
- Stopping Zscaler app from the UI is **not enough** — the Windows service must be stopped and disabled
- Both bypass rules (SSL inspection AND VPN gateway hostname) are required for coexistence
- Other OS platforms (macOS, Linux) are untested; Twingate does not confirm compatibility
