# Using Zscaler alongside Twingate

## Summary
Zscaler Client Connector on Windows can intercept the Twingate TLS session, so the Twingate Client sees an invalid certificate and cannot open secure channels. The fix is to either remove or disable Zscaler, or configure SSL inspection and VPN gateway bypasses for Twingate domains in the Zscaler admin console.

## Key Information
- **Applies to:** Twingate Client on Windows with Zscaler Client Connector. Other platforms are unconfirmed and untested, though the resolution should be the same if issues appear on macOS or Linux.
- **Cause:** Zscaler intercepts TLS to `<network>.twingate.com` and returns its own certificate. Twingate's certificate pinning check then fails.
- The Zscaler service on Windows keeps running even when the client is not connected. Exiting the program is not sufficient.

## Prerequisites
- Admin access to the Zscaler admin console and the Client Connector Portal.
- Your Twingate tenant name.
- Access to the Windows device, to stop the service or read `Twingate.log`.

## Symptoms (Twingate.log on Windows)
- `[WARN] [client] SSL check error from host: <twingate_network>.twingate.com. SSL Certificate is not pinned! [ApiCertificateValidationService.Callback]`
- `[ERROR] [client] Failed to validate controller url [ControllerServerValidator.ValidateAsync] System.Net.Http.HttpRequestException ... Could not establish trust relationship for the SSL/TLS secure channel ... The remote certificate is invalid according to the validation procedure.`

## Step-by-Step

**Option 1: Disable Zscaler**
1. Uninstall Zscaler, or stop the Zscaler service and set it to disabled.

**Option 2: Run both with bypass configuration (works in some cases)**
1. In the Zscaler admin console, go to Administration → IP & FQDN Groups → Destination IPv4 Groups.
2. Create a group for SSL inspection bypass and add `.twingate.com`.
3. Go to Policy → Zscaler Client Connector Portal → Windows.
4. Edit the applicable policy. Under HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY, add `<tenant>.twingate.com` as an exception, replacing `<tenant>` with your tenant name.
5. Update the policy on the Zscaler local agent so the changes take effect.

## Configuration Values
- SSL inspection bypass group entry: `.twingate.com`
- VPN gateway bypass entry: `<tenant>.twingate.com`
- Log file to check: `Twingate.log`

## Gotchas
- Closing or exiting the Zscaler app does not stop interception. The service must be stopped and disabled, or Zscaler uninstalled.
- The bypass configuration is not guaranteed to work in every environment ("in some cases").
- The policy must be refreshed on the local Zscaler agent after you edit it.
- The leading dot in `.twingate.com` covers subdomains. The VPN gateway bypass uses your specific tenant hostname.
