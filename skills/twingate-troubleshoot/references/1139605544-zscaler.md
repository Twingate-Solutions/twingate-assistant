# ZScaler Compatibility with Twingate

## Page Title
ZScaler Integration / Conflict Resolution

## Summary
ZScaler intercepts Twingate's TLS sessions on Windows, causing certificate validation failures that prevent the Twingate Client from establishing secure channels. Resolution requires either disabling ZScaler or configuring SSL inspection bypass rules for Twingate domains.

## Key Information
- **Affected component**: Twingate Client (Windows confirmed; macOS/Linux untested)
- **Root cause**: ZScaler performs TLS interception, returning an invalid certificate to the Twingate Client
- **ZScaler runs as a service** — exiting the UI application is insufficient; the service must be stopped/disabled
- Coexistence is possible with proper ZScaler bypass configuration

## Symptoms
Log entries in `twingate.log` on Windows:
```
[WARN] SSL check error from host: .twingate.com. SSL Certificate is not pinned!
[ERROR] Failed to validate controller url — The remote certificate is invalid according to the validation procedure.
```

## Resolution Options

### Option A: Disable ZScaler
Stop and disable the ZScaler Windows service entirely (not just quit the application).

### Option B: Configure ZScaler Bypass (Coexistence)

**Step 1 — Create SSL Inspection Bypass Group**
- Navigate to: `Administration → IP & FQDN Groups → Destination IPv4 Groups`
- Create a new group for SSL inspection bypass
- Add: `.twingate.com`

**Step 2 — Add VPN Gateway Hostname Bypass**
- Navigate to: `Policy → Zscaler Client Connector Portal → Windows`
- Edit the applicable policy under **HOSTNAME OR IP ADDRESS BYPASS FOR VPN GATEWAY**
- Add exception: `.twingate.com` (replace with your tenant name)

**Step 3 — Push Policy Update**
- Update policy on the ZScaler local agent

## Configuration Values
| Setting | Value |
|---|---|
| Domain to bypass | `.twingate.com` |
| ZScaler console path (SSL bypass) | `Administration → IP & FQDN Groups → Destination IPv4 Groups` |
| ZScaler console path (VPN bypass) | `Policy → Zscaler Client Connector Portal → Windows` |

## Gotchas
- Stopping the ZScaler application from the system tray does **not** stop the underlying Windows service — must explicitly stop/disable the service
- macOS and Linux compatibility with ZScaler is **unconfirmed/untested**; apply same resolution approach if issues occur
- Both bypass rules (SSL inspection AND VPN gateway) are required for coexistence — applying only one may not resolve the issue
