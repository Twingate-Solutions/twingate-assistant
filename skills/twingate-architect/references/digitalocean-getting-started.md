# Getting Started with DigitalOcean and Twingate

## Summary
Deploys a Twingate Connector on a DigitalOcean Droplet using `doctl` CLI and `cloud-init`. The Connector enables secure remote access to private DigitalOcean resources without exposing them publicly.

## Key Information
- Deployment method: `doctl` CLI + `cloud-init` script (command generated by Twingate Admin Console)
- Each Connector requires its own unique Access/Refresh token pair — never reuse tokens
- Verification required in both DigitalOcean Control Panel and Twingate Admin Console
- Successful state: Connector shows `Controller` and `Relay` statuses as **connected**

## Prerequisites
- DigitalOcean account with API access
- `doctl` CLI installed and authenticated with DigitalOcean credentials
- Twingate account with Admin Console access
- An existing Remote Network in Twingate

## Step-by-Step

1. **Generate Tokens**: Admin Console → Remote Networks → select network → add/select Connector → See More → DigitalOcean → Step 2 → **Generate Tokens**
2. **Copy install command**: Scroll to Step 4 in the Connector setup UI and copy the `doctl` command
3. **Run command**: Paste into terminal — creates a Droplet with Connector pre-configured via `cloud-init`
4. **Verify in DigitalOcean**: Control Panel → Droplets → confirm Droplet status is **running**
5. **Verify in Twingate**: Admin Console → Remote Networks → select network → select Connector → confirm Controller and Relay show **connected**

## Configuration Values
- Tokens (Access + Refresh) are embedded in the generated `doctl` command — no manual env var configuration needed
- Token generation triggered via Admin Console UI (not API/CLI)

## Gotchas
- **Token reuse**: Each Connector must have unique tokens; reusing token sets causes failures
- **Copy/paste whitespace**: Terminal whitespace interpretation may corrupt the command; paste into a script file if needed
- **`doctl` not found**: Must be installed and authenticated before running the generated command
- Tokens must be entered correctly in the `cloud-init` script — verify carefully if deployment fails

## Troubleshooting Commands
```bash
# Verify Droplet was created
doctl compute droplet list

# Check Connector service on the Droplet (SSH in first)
systemctl status twingate-connector
```
