# Privileged Access for Web Apps Overview

## Summary
Privileged Access for Web Apps is the web app component of Twingate Privileged Access Management. A Twingate Gateway acts as a Layer 7 reverse proxy for internal web apps (Web App Resources) and injects a signed ES256 JWT (Gateway Access Token) and optional identity headers into every request. Apps verify the JWT instead of integrating OIDC. The Gateway can also serve trusted HTTPS with certificates issued on demand from a registered CA.

## Key Information
- Flow: Browser → Twingate Client → Gateway → App. The Controller issues the GAT after authorizing the user's session and the Resource's Security Policy. No login redirect is needed.
- JWKS endpoint: `https://<your-tenant>.twingate.com/api/v1/jwk/ec` (unauthenticated). Use the full network address, including any regional part (e.g. `acme.us1.twingate.com`), because the short form can redirect.
- JWT header: `alg: ES256`, `typ: GAT` (not `JWT`), `kid`.
- Key claims: `aud` (network name), `exp`, `iat`, `user.*` (id, username, email, first_name, last_name, groups), `device.*` (id, location), `resource.*` (id, type=WEB_APP, address, aliases, gateway_metadata).
- Use cases: add identity to apps with no auth, SSO for trusted-header apps (Jenkins), SSO for JWKS-validating apps (Grafana), and trusted HTTPS without per-app certs.

## Prerequisites
- Twingate account with admin privileges
- Deployed Gateway with a Web App Resource
- At least one Connector in the same Remote Network
- For HTTPS: a CA registered with Twingate (self-signed, HashiCorp Vault, or Google Cloud CA Service) and user devices that trust it (manually or via MDM)

## Step-by-Step (Kubernetes Operator)
1. In the Admin Console, create a Remote Network and an API key with Read, Write & Provision permissions.
2. Install the Twingate Kubernetes Operator with the Gateway subchart and `gateway.webApp.enabled: true`. Add the alias and address to `gateway.tls.certificates.autoGenerated.dnsNames` (before Gateway 2.0: `gateway.tls.dnsNames`).
3. Annotate the app's Service with `resource.twingate.com: "true"`, `resource.twingate.com/type: "WebApp"`, `resource.twingate.com/gatewayName`, and `resource.twingate.com/requestHeaderRewrites`.
4. Deploy a Connector in the same Remote Network.
5. Grant users or Groups access to the Resource.
6. Verify the JWT in the app, or configure the off-the-shelf app to trust the injected headers.

## Configuration Values
- Template variables: `{{jwt}}`, `{{username}}`, `{{groups}}`, `{{clientGeoLatLong}}`, `{{clientGeoCity}}`, `{{clientGeoRegion}}`, `{{clientGeoCountry}}`
- Recommended header: `Authorization: Bearer {{jwt}}`. Fallback: `X-Twingate-User: {{username}}`, `X-Twingate-Groups: {{groups}}`. Use one approach, not both.
- Gateway-wide headers: Helm `gateway.webApp.requestHeaders`. Per-Resource headers: Admin Console, API, Terraform `twingate_web_app_resource.request_header_rewrites`, or `TwingateResource.spec.requestHeaderRewrites` (a list of name/value pairs). Per-Resource rewrites override Gateway-wide headers of the same name.
- Service annotations also include `downstreamPort` and `downstreamTLSMode` (e.g. `TLS13`).

## Gotchas
- Verification checks:
  - Accept `ES256` only and require `kid`.
  - Fetch keys only from your JWKS URL.
  - Don't require `typ=JWT`, and don't require `nbf`.
  - Pass `aud` explicitly.
  - `resource.address` must exactly equal the app's Resource address (not aliases or the Host header), because `aud` covers the whole network.
  - Require `exp` and `iat`, allowing 30s clock skew.
  - Reject tokens with no `user` or `user.email`.
- Return 401 for a missing or invalid token and 403 for insufficient groups. Never log or store the token.
- Ignore `Everyone` and `twingate:*` groups for authorization. The token lists only Groups that grant access to the Resource.
- Plain headers are unsigned, so restrict app access to the Gateway only (e.g. a Kubernetes NetworkPolicy).
- A Resource alias must be concrete, but its address can be a wildcard. Wildcards match one label, and the Gateway certificate must include a matching wildcard.
- Some SaaS apps that redirect to other domains or external IdPs are incompatible.
