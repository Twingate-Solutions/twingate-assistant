# Reviewing Access Requests

## Summary
Admins and designated Resource Approvers can approve or deny Access Requests generated by JIT access workflows or Usage-Based Auto Lock policies. Review process is identical regardless of which workflow triggered the request. Resolved requests are retained for 90 days.

## Key Information
- Access Requests page shows all open requests plus resolved requests from the last 90 days
- Red dot on bell icon in Admin Console indicates pending requests
- Resource Approvers only see the Access Requests page — no other Admin Console access
- Email notifications to Resource Approvers always fire; cannot be configured/suppressed
- Admins can also review open requests from individual User or Resource detail pages

## Who Can Review Requests

| Role | Scope |
|------|-------|
| Admin | All users and resources |
| DevOps | All users and resources |
| Access Reviewer | All users and resources |
| Resource Approver | Only assigned resources, any user |

## Prerequisites
- Resource Approvers must be assigned via the Resource detail page in the Admin Console
- Resource Approvers must be organized into Groups (groups are assigned, not individual users)
- Resource Approver users access the console via the standard URL (e.g., `https://autoco.twingate.com`)

## Configuring Resource Approvers (Step-by-Step)
1. Navigate to the Resource detail page in Admin Console
2. Open the Resource Approvers dialog
3. Assign one or more Groups as Resource Approvers
4. All members of assigned Group(s) gain review rights for that resource

## Gotchas
- Resource Approvers receive email notifications for **every** pending request — notification settings cannot be modified for this role
- Resource Approvers log in via the standard Admin Console URL but are restricted to the Access Requests page only
- Assign purpose-built Groups as Resource Approvers rather than reusing broad groups, since all group members receive notifications and gain approval rights
- Resource Approvers approve for any user on their assigned resources, but have zero visibility into other resources or admin functions
